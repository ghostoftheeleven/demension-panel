# Версии и релизы

## Номер версии `vX.Y.Z`

Правила задал владелец проекта; они **отличаются от обычного semver** (новые функции не повышают среднюю цифру).

| Цифра | Когда повышается | Примеры |
|---|---|---|
| **X** — мажор | Только сверхкрупные, масштабные переработки всей панели | Новая архитектура, несовместимый формат данных, переписанная панель |
| **Y** | Исправление **критических** уязвимостей и багов, которые приводили к утечкам данных или критическим сбоям работы панели | Обход авторизации, утечка секретов/ключей, потеря клиентов или VPN у всех пользователей, падение панели |
| **Z** | Всё остальное: обычные баги, потенциальные уязвимости, доработки и новые функции, не приводившие к серьёзным сбоям | Исправление интерфейса, новая настройка, ужесточение проверок, улучшение установщика |

При повышении цифры младшие обнуляются (`v0.3.7` → `v0.4.0`). Если в одном релизе есть и критическое исправление, и
доработки, номер выбирается по самому серьёзному изменению. Номер только растёт.

## Где хранится версия

- **Единственный источник** — поле `version` корневого `package.json` (без `v`). Сервер читает его при запуске
  (`services/version.service.ts`, `PANEL_VERSION`). `server/package.json` и `client/package.json` версию панели не задают.
- `CHANGELOG.md`: первый раздел `## vX.Y.Z — ГГГГ-ММ-ДД` — текущая версия, ниже — предыдущие по убыванию. Текст раздела
  становится описанием релиза на GitHub. Согласованность проверяет `test/version.test.ts`.

## Как выпустить версию

1. Повысить `version` в корневом `package.json` по правилам выше.
2. Добавить в начало `CHANGELOG.md` раздел `## vX.Y.Z — дата` с описанием изменений для администратора панели (что
   исправлено/добавлено, нужно ли что-то сделать после обновления).
3. Закоммитить вместе с изменениями и запушить в `main`.
4. После зелёного CI workflow `.github/workflows/release.yml` (скрипт `.github/scripts/release.sh`) создаёт тег `vX.Y.Z`
   и релиз GitHub с текстом из `CHANGELOG.md`. Если тег уже есть — ничего не делает; если версия меньше последнего
   релиза или нет раздела в `CHANGELOG.md` — падает.

Правки без изменения поведения (документация, тесты, CI) версию не меняют и релиз не создают. Изменения, которые
копятся в `main` без повышения версии, попадут в следующий релиз — не забывайте записывать их в `CHANGELOG.md`
(раздел следующей версии можно завести заранее, повысив версию в том же коммите).

## Проверка обновлений в панели

`GET /api/version` → `VersionService.getInfo`: текущая версия и последний релиз
`https://api.github.com/repos/ghostoftheeleven/demension-panel/releases/latest`.

- Ответ кэшируется на 6 ч, после ошибки — повтор через 30 мин; `?refresh=1` (клик по версии в шапке) — не чаще раза в минуту.
- Ответ GitHub — внешние данные: принимается только тег `vX.Y.Z` и ссылка на страницу релиза этого репозитория.
- `DEMENSION_UPDATE_CHECK=0` в `server/.env` отключает обращения к GitHub.
- В шапке интерфейса (`PanelVersion.tsx`): текущая версия, «актуальная (GitHub: vX.Y.Z)» или ссылка «Доступна vX.Y.Z».
- Панель не обновляется сама: обновление — повторный запуск `install.sh` (README).
