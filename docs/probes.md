# Проверка доступности нод из стран

Панель стоит в одной стране, а пользователи — в разных, и нода, доступная панели, может быть заблокирована у них. Функция
показывает, **достучались ли до адреса ноды проверяющие узлы выбранных администратором стран**, на карточках нод и в подписке.

Код — `server/src/services/probe.service.ts`, заглушка — `services/stub.service.ts`, API — `routes/probes.ts`, интерфейс — `ProbesCard.tsx` (раздел «Серверы»),
`ProbeBadges.tsx`, вывод в подписке — `routes/subscription.ts`.

## Как это работает

Проверку выполняют узлы публичного сервиса **check-host.net** (бесплатный API без ключа, ~50 узлов в ~30 странах: список
берётся у сервиса, администратор выбирает до 8 стран). Раз в интервал (10–1440 мин, по умолчанию 30) панель для каждой
установленной ноды:

1. выбирает по два проверяющих узла от каждой выбранной страны;
2. если на ноде ещё нет **заглушки** — ставит её по SSH (см. ниже);
3. отправляет узлам `check-http` на `http://нода:порт/<метка>` (одноразовая метка проверки) и `check-udp` на `нода:порт`;
4. опрашивает `check-result`, пока узлы не ответят (до 45 с; не ответившие в итог не входят);
5. по SSH читает **журнал заглушки** на ноде и сверяет, чьи обращения действительно дошли (`matchStubHits`);
6. сохраняет по стране `ok_nodes / total_nodes`, `tcp_ok`, `udp_ok`, `spoofed`, `verified` и среднюю задержку в `probe_results`.

**Почему не ping.** Ответ ICMP (как и TCP-рукопожатие) провайдер или ТСПУ может подделать — «нода доступна», хотя пакеты до неё не
доходят. Поэтому ping больше не используется. Запись же в журнале на самой ноде подделать нельзя: она появляется, только если
пакет действительно дошёл.

**Заглушка** (`services/stub.service.ts`) — отдельный контейнер `dementia-probe` (`alpine:3.20` + socat, сеть хоста, каталог
`/opt/dementia-probe`) на случайном свободном порту 20000–60999 (кроме распространённых портов, порта AmneziaWG и SSH). По TCP она отдаёт
нейтральную страницу «Coming soon» с меткой `stub_token` в комментарии, на любой UDP-пакет отвечает `ok`; каждое обращение пишется в
`hits.log` (время, адрес отправителя, путь запроса; журнал ограничен 1 МБ). Контейнер AmneziaWG она не трогает. Переустановка сохраняет
порт, если он свободен; пропавший контейнер замечается при чтении журнала (`stub_port` сбрасывается, следующий обход ставит заново).
Заглушка ставится только при включённой проверке; удаление ноды с очисткой удаляет и её.

**Как считается результат.** Узел засчитывается, если до заглушки дошёл его **UDP**-пакет (так ходит трафик AmneziaWG); если UDP-проверку
запустить не удалось или узел её не закончил — по TCP с меткой. Обращение с меткой с незнакомого адреса (узел вышел в сеть не с того адреса,
что сообщил check-host.net) засчитывается узлу, который сообщил об успехе, и этот адрес используется для UDP. Узел, получивший «ответ»,
хотя в журнале его нет, считается **подменой** (`spoofed`, знак ⚑ в интерфейсе). Если журнал прочитать не удалось, засчитываются ответы
узлов без подтверждения (`verified = 0`), это отмечается в ошибке.

Статус страны: **доступна** (дошли все узлы страны), **не везде** (часть), **недоступна** (никто). Пока проверка идёт,
прежние результаты остаются; результаты старше трёх интервалов (но не менее двух часов) считаются устаревшими и нигде не
показываются.

**Ноды без заглушки.** На ноды партнёров заглушку не поставить (нет SSH). Для них, а также для своей ноды, на которую заглушку поставить
не удалось, проверяется TCP-подключение к заданному администратором порту (`servers.probe_port`) по ответу check-host.net — без
подтверждения на ноде (`method = 'tcp'`). Без порта такая нода не проверяется (ошибка в `probe_error`).

**Что это показывает, а что нет.** Заглушка выявляет блокировку адреса ноды и блокировку UDP. Блокировку именно протокола AmneziaWG
(DPI при открытом адресе и UDP) так не увидеть, а узлы check-host.net стоят в дата-центрах — фильтрация только мобильных сетей им не видна.
Для этих случаев есть сигнал от клиентов и режим «всегда через мост» ([bridges.md](bridges.md)).

После каждого обхода вызывается `ProbeService.afterRun` (задаёт `index.ts`): сквозная проверка мостов и пересчёт, кому нужен мост.

## Приватность

Функция **выключена по умолчанию**: пока администратор её не включил, панель не обращается к check-host.net и не ставит заглушки на ноды. После включения
сервису передаются адреса (IP/домены) нод и выбранные страны — об этом предупреждает интерфейс. Все ответы сервиса считаются
внешними данными и проверяются по формату: идентификатор узла (`*.node.check-host.net`), код страны (две буквы), идентификатор
запроса (`[A-Za-z0-9]{3,40}`), числа конечны. Недоступность сервиса не ломает панель: ошибка записывается
(`probe_error`), результаты остаются прежними.

## Подписка

Если проверка включена и есть свежие результаты:

- **название ноды** получает пометки: `Frankfurt · 🇷🇺✅ 🇰🇿❌` (✅ доступна, ⚠️ не везде, ❌ недоступна; порядок стран — как
  выбрал администратор). Имя берётся прежнее (`sub_name` или имя сервера). Работает во всех форматах: Incy (`#имя`), JSON, mihomo.
  Отключается флажком «Показывать в названии ноды». Пометки меняются вместе с результатами, а в клиентах mihomo имя прокси —
  ключ выбора, поэтому выбранную вручную ноду при смене пометки придётся выбрать заново (для таких случаев флажок и нужен);
- **описание подписки** (`Profile-Description`, как `base64:…`) дополняется строкой «Доступность нод из стран: 🇷🇺 Россия, … ✅ доступна …
  Проверено 25.10 14:30 UTC». Отключается флажком «Пояснение в описании подписки».

Заголовки остаются ASCII (инвариант 19): текст передаётся как `base64:`.

## API `/api/probes` (администратор)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | `{settings, status:{running,last_run,error,next_run}, max_countries, servers:[{id,name,host,status,probe_port,stub_port,remote_panel_id}], results}` |
| GET | `/countries` | Страны, где есть проверяющие узлы: `[{code, name, nodes[], cities[]}]` (кэш сутки; 502, если сервис недоступен) |
| PUT | `/` | `{settings?:{enabled, countries[], interval_minutes, show_in_name, show_in_description}, servers?:[{id, probe_port}]}`; включение требует хотя бы одну страну; смена способа проверки сервера или списка стран удаляет прежние результаты |
| POST | `/run` | Проверить сейчас (фоном, 202); не чаще раза в минуту (429), не при выключенной функции (400) |

`GET /api/servers` содержит `probes: [{country, method, ok_nodes, total_nodes, tcp_ok, udp_ok, spoofed, verified, rtt_ms, checked_at, status}]` (пусто, пока функция
выключена или данных нет).

## Данные

Миграция v8: `servers.probe_port` и таблица `probe_results(server_id, country, ok_nodes, total_nodes, rtt_ms, checked_at)` с каскадным
удалением. Миграция v9: `servers.stub_port`, `servers.stub_token` (метка страницы заглушки, не секрет) и колонки `probe_results`:
`method` (`stub`/`tcp`; старые записи — `ping`), `tcp_ok`, `udp_ok`, `spoofed`, `verified`. Настройки (`settings`): `probe_enabled`,
`probe_countries` (JSON), `probe_interval`, `probe_in_name`, `probe_in_description` (`0` — выключено), `probe_last_run`, `probe_error`.

Фоновый цикл `probeLoop` (`index.ts`) раз в минуту проверяет `ProbeService.isDue()` и пересчитывает состояние мостов по сигналу от
клиентов; на время переноса панели ([migration.md](migration.md)) он на паузе.
