# Резервные копии

Панель создаёт зашифрованные архивы в Яндекс Диске или Google Drive. Подключение находится в разделе **«Безопасность» → «Резервные копии»**. Автоматическое копирование выключено по умолчанию; после включения оно выполняется раз в 24 часа, хранятся 10 последних копий. Период и ограничение списка можно изменить.

## Хранилища

- **Яндекс Диск:** логин и отдельный пароль приложения. Архивы загружаются по WebDAV в `dementia-panel` на `https://webdav.yandex.ru`.
- **Google Drive:** OAuth 2.0 пользователя (`client_id`, `client_secret`, `refresh_token`) и необязательный ID папки. Service account не используется: копии принадлежат Google Drive пользователя.

Облачные пароли и токены зашифрованы мастер-ключом панели. Внешние запросы имеют таймаут, а ответы проверяются по формату.

## Содержимое и шифрование

Снимок SQLite создаётся через `VACUUM INTO`; в архив входят БД, `secret.key` и TLS-файлы из белого списка. Сессии и служебное состояние переноса исключаются. Архив шифруется отдельным случайным 256-битным ключом восстановления (AES-256-GCM), а сам ключ хранится в БД под мастер-ключом. Показ ключа требует пароль администратора.

**Сохраните ключ восстановления отдельно от облачного хранилища.** Без него архив расшифровать нельзя. Ключ нужен вместе с файлом `.dpm`, а не вместо него.

## Восстановление

Остановите службу панели, скачайте архив и выполните на сервере:

```bash
node server/dist/cli/restore-backup.js /путь/к/копии.dpm 'КЛЮЧ_ВОССТАНОВЛЕНИЯ'
```

Либо из каталога `server`: `npm run restore-backup -- /путь/к/копии.dpm 'КЛЮЧ'`.

CLI расшифровывает архив, проверяет версию схемы и мастер-ключ, затем заменяет данные. Прежний каталог данных сохраняется в `data/backups/pre-backup-<дата>`; при ошибке файлы откатываются. После восстановления запустите службу панели. HTTP-восстановления намеренно нет: его нельзя безопасно выполнить внутри процесса, который использует восстанавливаемую БД.

## Фоновые задачи и журнал

Одновременно выполняется только одна копия. Во время переноса панели копирование приостанавливается. Успешные загрузки и ошибки попадают в журнал событий и, при подключении, в Telegram.
