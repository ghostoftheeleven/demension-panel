# Безопасность

Уязвимости, найденные при аудите, описаны в приватных Security Advisories репозитория. Ниже — механизмы, которые
их закрывают; не ослабляйте их.

## Авторизация администратора
- Пароль — scrypt с солью (`AuthService.hashPassword`), сравнение `timingSafeEqual`; для несуществующего логина тоже
  вычисляется хэш (нет перебора логинов по времени).
- Логин и пароль администратора **случайные** (`AuthService.randomLogin/randomPassword`: логин — буква и 9 символов a-z0-9, пароль —
  20 символов A-Za-z0-9; «admin» не используется). `install.sh` генерирует их при первой установке и показывает в консоли **один
  раз**; без `PANEL_USER`/`PANEL_PASSWORD` при первом запуске сервера недостающее тоже генерируется и выводится в лог один раз.
  Пароль из окружения нигде не печатается. Учётные данные записываются в БД через `cli/reset-admin.ts` (без параметров он выдаёт
  новый случайный пароль при прежнем логине), в `.env` пароль не хранится (`.env` — 600).
- Сессии: 7 дней, в БД — SHA-256 токена; смена пароля завершает все сессии и выдаёт новый токен.
- Логин: не более 5 неудач за 15 мин с IP и 10 — на логин (`FailureLimiter`), затем 429. Блокировка по логину (защита
  от перебора с множества адресов) не действует на IP, с которого администратор уже входил (`trusted_login_ips`, 30 дней,
  `AuthService.rememberLoginIp`), — иначе любой мог бы закрыть администратору вход, отправив 10 неверных паролей. Лимит
  по IP действует всегда. Счётчики хранятся в памяти: после `reset-admin` они сбрасываются перезапуском службы
  (`systemctl restart demension`); сам сброс учётных данных забывает известные IP.
- Смена логина и пароля, выдача кода переноса требуют текущий пароль; неверные пароли считает `reauthLimiter` — 5 за 15 минут
  на администратора, затем 429 (украденная сессия не должна позволять подбирать пароль). Смена логина, как и пароля, завершает остальные
  сессии и выдаёт новый токен. Логин — до 64 символов `A-Za-z0-9._@-` (тот же набор проверяет `install.sh`).
- Токен — только в `Authorization: Bearer`. WebSocket `/ws`: первое сообщение `{type:'auth', token}` в течение 10 с,
  `maxPayload` 64 КБ, обработчик `error` на каждом сокете.

## Секреты
- `encryptSecret`/`decryptSecret` (AES-256-GCM, формат `enc:v1:`), ключ — `DEMENSION_SECRET_KEY` (base64, 32 байта)
  или `data/secret.key` (создаётся с правами 600). **Без ключа зашифрованные данные не восстановить** — бэкап всего
  `data/`. `install.sh` при обновлении переписывает в `server/.env` только `PORT` и `NODE_ENV`, добавленные вручную
  переменные (`DEMENSION_SECRET_KEY`, `TRUST_PROXY`…) сохраняет, а `PANEL_USER`/`PANEL_PASSWORD` старых версий удаляет.
- Шифруются: `servers.ssh_password`, `servers.ssh_key`, `settings.cf_token`, `remote_panels.token`.
- Приватный ключ TLS — `data/ssl/privkey.pem` с правами 600. Каталог `data/` в `.gitignore`.

## SSH к нодам
- TOFU: отпечаток ключа хоста сохраняется при первом подключении (`servers.host_key`), несовпадение → ошибка, статус
  `error`. Сброс — в настройках сервера (или автоматически при смене host).
- Таймауты команд, keepalive, `sudo -n` для не-root.
- Скрипт установки и конфиги передаются через stdin, а не временные файлы.

## Перенос панели
Подробно — [migration.md](migration.md). Архив переноса содержит ключ шифрования и приватный ключ TLS, поэтому шифруется (AES-256-GCM)
ключом, выведенным из кода переноса (25 случайных символов, ≈125 бит, показывается один раз). Код по сети не передаётся и не хранится: запросы
подписаны производной `auth`, на прежней панели лежит только её SHA-256; неверные коды ограничены (10 за 15 минут с IP). Поэтому архив безопасен
и по HTTP, и при самоподписанном сертификате прежней панели. В архив попадают только файлы из белого списка; при импорте БД отвергается,
если создана более новой схемой или секреты не расшифровываются ключом из архива (прежние файлы восстанавливаются). Пока архив передан,
панель не принимает записи (423), после переноса — заморожена (410), ссылки подписок перенаправляются на новый адрес.

## Проверка доступности из стран
Функция выключена по умолчанию; после включения адреса нод и выбранные страны отправляются на check-host.net (интерфейс предупреждает). Ответы сервиса
проверяются по формату до использования, идентификатор запроса и узлов подставляются в URL только после проверки. См. [probes.md](probes.md).

## Проверка обновлений
- Панель запрашивает `api.github.com/repos/ghostoftheeleven/demension-panel/releases/latest` (не чаще раза в 6 ч, только
  после входа администратора; в запросе — лишь `User-Agent: demension-panel/<версия>`). Ответ проверяется по формату
  (тег `vX.Y.Z`, ссылка только на релизы репозитория). Отключение: `DEMENSION_UPDATE_CHECK=0` в `server/.env`.
- Обновление из интерфейса (`POST /api/version/update`, только администратор) ставит только последний релиз `vX.Y.Z` из GitHub
  (тег проверяется по формату и в панели, и в скрипте; значения в `systemd-run` передаются массивом аргументов, без shell).
  Журнал обновления не содержит секретов: `install.sh` в режиме обновления не создаёт учётные данные. Отключение: `DEMENSION_SELF_UPDATE=0`.
- `/api/health` версию не раскрывает: версия доступна только администратору (`/api/version`).

## Ввод данных
- Валидация в роутерах (подсети, порты, хосты, имена, параметры AWG, URL, email).
- Удалённые команды — `shellQuote`; локальные — `execFile` (fail2ban: `net.isIP` + массив аргументов).
- Все SQL — параметризованные; имена колонок в динамических UPDATE берутся только из фиксированных списков.
- **Данные чужой панели** (ноды и клиенты партнёра) подставляются в .conf наших пользователей, поэтому проверяются по формату
  (`sanitizeRemoteNode`, `sanitizeRemotePeer`, `sanitizeRemoteParams`): адрес, порт, ключи, IP, параметры обфускации. Перевод
  строки в значении позволил бы дописать в чужой конфиг директиву (например, `PostUp` — команда на устройстве клиента).
  Нода с некорректными данными получает `uninstalled` и пропадает из подписок. То же правило для подписи I1–I5 локальных
  параметров (`isValidSignature` не принимает переводы строк).
- Ключ AmneziaVPN распаковывается с лимитом 1 МиБ (защита от «бомбы»); в журнал логин неудачной попытки входа пишется
  через `JSON.stringify` (нельзя подделать записи).

## Заголовки и ошибки HTTP
- `securityHeaders` (middleware/security-headers.ts): CSP (`script-src 'self'`, без внешних источников, `frame-ancestors 'none'`),
  `X-Frame-Options`, `nosniff`, `Referrer-Policy`, HSTS по HTTPS. Новые ресурсы интерфейса должны быть локальными.
- `errorHandler` (middleware/error-handler.ts) — общий для панели и тестов: `HttpError`, некорректный JSON (400), большое тело (413),
  прочие 4xx Express (битая %-кодировка пути) отдаются клиенту как есть, остальное — 500 без подробностей.

## HTTPS на одном порту
`index.ts`: `net.Server` смотрит первый байт соединения — `0x16` (TLS ClientHello) идёт в `https.Server`, остальное —
в `http.Server`. Поэтому:
- проверка запуска `/api/health` доступна и по HTTP (иначе `install.sh` принимал бы обновление такой панели за сбой);
- сертификат меняется без перезапуска (`setSecureContext` через `SslService.onCertificateChanged`);
- при включённом HTTPS по HTTP доступны только `/sub/*` и ACME-challenge, остальное — 302 на HTTPS, `/api/*` — 403.
  Хост редиректа берётся из домена сертификата (`ssl_domain`), а не из заголовка `Host` (`httpsRedirectLocation`),
  чтобы запрос с чужим `Host` не получил редирект на сторонний сайт; из `Host` берётся только порт. Без пригодного
  домена — 403;
- WebSocket по HTTP при включённом HTTPS отклоняется.
Let's Encrypt: ACME-аккаунт сохраняется (`acme-account.key`), HTTP-01 поднимает временный сервер на 80 порту, если
панель не на нём; продление за 30 дней до окончания; дата окончания читается из сертификата.

## Партнёрский API
Только HTTPS, токен-хэш, ограничение частоты и подбора, журнал действий. См. [partners.md](partners.md).

## Заголовки
`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, HSTS по HTTPS.
CORS отключён (SPA на том же origin, в разработке — прокси Vite).

## fail2ban
На хосте панели и нодах: jail `sshd`, порт из `sshd -T`, backend `auto`/`systemd`, на нодах `ignoreip` с IP панели
(иначе опрос со старым паролем заблокирует панель на 24 ч).
