# Эксплуатационная надёжность и защита панели — дизайн

## Цель

Выпустить v0.2.5 с обязательными критическими CI-проверками, зашифрованными резервными копиями во внешние хранилища, журналом событий и Telegram-уведомлениями, оптимизированным опросом данных, необязательной 2FA и управлением сессиями, а также первыми клиентскими тестами.

## Решения

### CI и быстрые исправления

- Убрать `continue-on-error` у `install` и `e2e`: релиз не должен выходить при неработающей установке или Docker-сценариях.
- Переименовать «Клиенты онлайн» в «Включённые клиенты», убрать упоминание неподдерживаемого HAPP.
- Добавить MIT `LICENSE`, `SECURITY.md` и Dependabot для npm и GitHub Actions.

### Резервные копии

- Хранилища: Яндекс Диск через WebDAV (`https://webdav.yandex.ru`, логин и пароль приложения) и Google Drive через OAuth 2.0 (`client_id`, `client_secret`, `refresh_token`, необязательный `folder_id`). Секреты — только через `encryptSecret`.
- Панель раз в сутки создаёт консистентный снимок SQLite через `VACUUM INTO`, включает БД, `secret.key` и TLS-файлы из существующего белого списка архива. Сессии в архив не попадают.
- Архив шифруется отдельным случайным 256-битным ключом через существующий `sealArchive`. Ключ хранится в БД зашифрованным мастер-ключом; администратор может показать его после подтверждения пароля и сохранить для восстановления после потери сервера.
- По умолчанию: копирование выключено, период 24 часа, хранить 10 последних архивов. Интерфейс: подключение и проверка хранилища, «Создать сейчас», список удалённых копий, скачивание, удаление, последний результат и ошибка.
- Восстановление выполняется отдельным CLI при остановленной панели: архив + ключ восстановления, с сохранением прежнего каталога данных. Автовосстановление из UI не добавляется.
- Фоновая задача проверяет `MigrationService.isBackgroundPaused()` и не запускает одновременно две копии.

### События и Telegram

- Новая таблица `events`: уровень, тип, текст, необязательные сущность и время. Хранить последние 5000 записей; секреты и конфиги не записывать.
- Фиксируются входы и изменения учётной записи, операции с нодами/пользователями, переходы доступности, ошибки синхронизации, TLS, обновления, резервные копии и 2FA.
- Отдельная вкладка «События» с фильтром по уровню и постраничной загрузкой.
- Подключение Telegram-бота по токену и `chat_id`; токен шифруется. По умолчанию отправляются предупреждения и ошибки, информационные события можно включить. Есть проверка подключения. Сбой Telegram не влияет на панель и не порождает рекурсивное событие.

### 2FA и сессии

- Необязательный TOTP (RFC 6238, SHA-1, 30 секунд, допустимое окно ±1 шаг) на Node `crypto`, без нового серверного пакета.
- Настройка: сгенерировать секрет и `otpauth://`, подтвердить пароль и текущий код, затем показать одноразовые коды восстановления. В БД — зашифрованный TOTP-секрет и SHA-256 кодов восстановления.
- При включённой 2FA вход сначала возвращает `totp_required`; принимается текущий TOTP или неиспользованный код восстановления.
- Сессии получают IP, User-Agent и время последней активности. Администратор видит список и отзывает любую сессию; текущая помечается отдельно.

### Производительность и клиент

- `GET /api/subscribers` получает суммы трафика и пиры агрегированными запросами вместо двух запросов на каждого пользователя.
- Опрос пропускается в скрытой вкладке и не допускает перекрытия одинаковых загрузок; настройки загружаются реже, клиенты — только выбранной ноды.
- Добавить Vitest/jsdom/Testing Library и тесты критических компонентов. Крупные вкладки загружать через `React.lazy` без смены роутинга или библиотеки состояния.

## Ограничения

- Сохранить все инварианты `AGENTS.md`: секреты в API не отдавать, токен авторизации только Bearer, новые поля — новой миграцией, фоновые циклы ставить на паузу при переносе.
- Тексты UI и ошибки — на русском; оформление Bento и семантические цвета.
- Google Drive не реализовывать через service account: используется OAuth пользователя с refresh token, чтобы копии принадлежали его Drive.
- Внешние HTTP-ответы считать недоверенными, ограничивать время запроса и проверять формат данных.
- Версия — `0.2.5` в корневом `package.json`; изменения описаны в `CHANGELOG.md` и документации подсистем.

## Проверка

- Сервер: новые unit/API/CLI-тесты, затем `npx tsc --noEmit && npm test`.
- Клиент: компонентные тесты, `npx tsc -b && npm run lint && npm test && npx vite build`.
- Shellcheck для изменённых скриптов; полные install/Docker E2E — в CI, если локальное Docker-окружение недоступно.
