# Мосты в странах пользователей

Мост — сервер в стране пользователей (например, VPS в России), через который они подключаются к зарубежной ноде, когда напрямую
она недоступна: заблокирован её адрес, режется UDP до зарубежных сетей, действуют белые списки. Подписка пользователя, у которого
задана страна, сама выдаёт адрес моста этой страны для тех нод, где это нужно.

Код — `server/src/services/bridge.service.ts`, `routes/bridges.ts`, скрипт установки `server/src/scripts/deploy-bridge.sh`, подмена
адреса — `routes/subscription.ts`; интерфейс — `BridgesView.tsx`, `BridgeModal.tsx` (вкладка «Мосты»), страна пользователя —
`AddSubscriberModal.tsx`.

## Как устроен мост

Мост **пересылает пакеты** правилами iptables (DNAT + MASQUERADE), а не расшифровывает трафик:

- UDP `мост:listen_port` → `нода:awg_port` — трафик AmneziaWG; шифрование остаётся сквозным, ключей пользователей на мосту нет,
  конфигурация клиента отличается от прямой только строкой `Endpoint`;
- TCP `мост:listen_port` → `нода:stub_port` — на заглушку проверки доступности ноды ([probes.md](probes.md)); через неё панель
  проверяет пересылку целиком (см. «Сквозная проверка»). Если заглушки на ноде нет, TCP не пересылается.

Docker на мосту не нужен. Установка (`deploy-bridge.sh`, по SSH через stdin, как установка ноды): ставит iptables при необходимости,
включает `net.ipv4.ip_forward`, записывает `/etc/dementia-bridge/rules.sh` и службу `dementia-bridge.service`, которая применяет
правила после перезагрузки (без systemd правила восстановит панель при очередном опросе).

`rules.sh` **генерируется целиком из БД** (`buildBridgeRules`, как конфиг ноды): цепочки панели `DEMENTIA-BRIDGE` (nat PREROUTING),
`DEMENTIA-BRIDGE-POST` (nat POSTROUTING) и `DEMENTIA-BRIDGE-FWD` (filter FORWARD) очищаются и заполняются заново. Переходы в них
ставятся **первыми** в цепочках (прежние удаляются): политика DROP в FORWARD от Docker или ufw иначе отбрасывала бы пересылаемый
трафик. DNAT срабатывает только для пакетов на адреса самого моста (`-m addrtype --dst-type LOCAL`) — исходящий трафик контейнеров
на мосту не перехватывается. Адрес ноды подставляется только после проверки (`isValidHost`) и в кавычках `shellQuote`; домен
разрешается на мосту (`getent ahostsv4`) при каждом применении. Ноды с IPv6-адресом не поддерживаются.

**Порт на мосту** для новой ноды — её порт AmneziaWG, если он не занят другой нодой этого моста и не совпадает с SSH-портом, иначе
случайный 20000–60999. У уже привязанной ноды порт не меняется: иначе пользователи с подпиской, полученной через мост, потеряют VPN.

## Привязка и режимы

У каждой пары мост × нода (`bridge_links`) свой режим:

| Режим | Что выдаёт подписка пользователям страны моста |
|---|---|
| `auto` (по умолчанию) | Адрес моста, пока для этой ноды и страны действует состояние «нужен мост» (`bridge_state.active`) |
| `always` | Всегда адрес моста — для блокировок, которые проверки не видят (белые списки мобильных операторов) |
| `off` | Прямой адрес; правила пересылки при этом остаются |

Мост выдаётся, только если он `online` и сквозная проверка пересылки не провалилась (`check_ok` не `0`). Если у ноды несколько
подходящих мостов в стране, берётся мост с меньшим id. В названии ноды появляется пометка `· 🌉 🇷🇺`. Подмена адреса работает во
всех форматах подписки (Incy, JSON, mihomo); выданные вручную файлы `.conf` и QR-коды не меняются.

## Кому нужен мост: решение с гистерезисом

`BridgeService.evaluate` пересчитывает `bridge_state` для каждой пары нода × страна, у которой есть мост в режиме `auto`.

**Проверка из страны** ([probes.md](probes.md)) — проблема, если до ноды дошли меньше половины узлов страны (`ok_nodes * 2 < total_nodes`).
Серии считаются только после проверок (`evaluate(true)` из `ProbeService.afterRun`), каждая проверка — один шаг:

- мост включается после **2** проблемных проверок подряд (`FAIL_STREAK_TO_ACTIVATE`);
- выключается после **3** проверок подряд без проблем (`OK_STREAK_TO_RELEASE`) и не раньше чем через **12 часов** после включения
  (`BRIDGE_HOLD_MS`) — пользователи не должны метаться между адресами при каждом обновлении подписки;
- если нода недоступна самой панели (`status != 'online'`), состояние не меняется: мост тут не поможет.

**Сигнал от клиентов** (`passiveSuspect`) — проверка не видит блокировку протокола (DPI) и мобильные сети, а клиенты видят. Сигнал есть, если:

- у клиентов ноды из страны (страна подписчика) за последние 6 часов были рукопожатия, и минимум **3** из них последний раз
  связались с нодой в пределах **10 минут** друг от друга (не меньше 60% клиентов страны, активных в последний час перед обрывом);
- с тех пор прошло не меньше **15 минут** тишины;
- у клиентов других стран (или без страны) рукопожатие было за последние 5 минут — нода жива.

Одновременность отличает блокировку от того, что пользователи выключали VPN по одному (например, вечером). Сигнал от клиентов включает
мост сразу (в нём уже есть 15 минут ожидания); пересчёт идёт каждую минуту (`probeLoop`). Выключение — как выше; если страна не
проверяется из стран, мост выключается по истечении 12 часов, когда сигнал от клиентов пропал. После перехода на мост рукопожатия клиентов
возобновляются (уже через мост), поэтому сигнал гаснет сам.

Без страны у пользователя мост ему не выдаётся. Сигнал от клиентов и проверку можно сочетать: мост включается по любому из них.

## Фоновые проверки

- `BridgeService.checkAll` (из `statsLoop`, каждые 30 с): если правила в БД изменились (порт или адрес ноды, заглушка, удалённая нода —
  сравнивается SHA-256 с `bridges.rules_hash`) или стоит `needs_apply`, правила применяются заново; раз в две минуты мост проверяется по
  SSH — правила на месте, переход в FORWARD первый. Правила пропали или сдвинуты — `needs_apply`. Три неудачи SSH подряд — `offline`.
  Мосты в статусе `error` (неудачная установка, смена ключа SSH-хоста) автоматически не трогаются.
- **Сквозная проверка** `checkLinks` (после каждой проверки из стран): панель открывает `http://мост:listen_port/<случайный путь>`; мост
  пересылает TCP на заглушку ноды, и ответ должен содержать её метку `stub_token`. Ответа нет или метка чужая — `check_ok = 0`, мост
  для этой ноды не выдаётся, пока следующая проверка не пройдёт.
- Все операции с одним мостом идут через ту же очередь `runExclusive`, что и ноды, по ключу `bridge:<id>`. На время переноса панели
  циклы на паузе.

## API `/api/bridges` (администратор)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | Мосты с `links: [{server_id, server_name, server_host, awg_port, listen_port, mode, check_ok, checked_at, active, reason, changed_at}]` |
| POST | `/` | `{name, host, ssh_port?, ssh_user?, ssh_password \| ssh_key, country, links?, install?}` — добавить и сразу установить (`install: false` — только добавить); ответ `{success, error?, log, bridge}` |
| PUT | `/:id` | Имя, адрес, SSH-доступ, страна (`reset_host_key: true` — сбросить ключ хоста) |
| PUT | `/:id/links` | `{links: [{server_id, mode}]}` — ноды моста; правила применяются сразу, при ошибке привязки возвращаются к прежним (502) |
| POST | `/:id/install` | Установка (повторная) с журналом |
| POST | `/:id/apply` | Применить правила |
| POST | `/:id/test-ssh` | Проверка SSH |
| DELETE | `/:id` | `?teardown=1` — убрать цепочки и автозапуск с сервера, `&force=1` — удалить из панели даже при ошибке |

SSH-пароль и ключ моста хранятся зашифрованными и в ответах не отдаются (`has_ssh_password`, `has_ssh_key`). Страна пользователя —
поле `country` в `POST/PUT /api/subscribers` (двухбуквенный код, пусто — не задана).

## Данные

Миграция v9: таблицы `bridges` (SSH-доступ как у серверов, `country`, `status`, `rules_hash`, `needs_apply`, `fail_count`, `last_error`),
`bridge_links(bridge_id, server_id, listen_port, mode, check_ok, checked_at)` (уникальны пара мост × нода и порт на мосту; каскадное
удаление вместе с мостом и нодой) и `bridge_state(server_id, country, active, fail_streak, ok_streak, reason, changed_at)`, колонка
`subscribers.country`.
