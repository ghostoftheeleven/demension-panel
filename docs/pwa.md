# Панель как приложение (PWA)

Панель можно установить на телефон (Android, iOS) и на компьютер: она откроется в отдельном окне без адресной строки, с иконкой на домашнем
экране, запомнит вход и покажет понятный экран «Нет связи» вместо ошибки браузера, если сети нет. Код — `client/public` (манифест, сервис-воркер,
иконки), `client/src/pwa.ts`, `InstallAppButton.tsx`, `ConnectionLost.tsx`, `server/src/middleware/static-cache.ts`.

## Что нужно для установки

| Условие | Зачем |
|---|---|
| **HTTPS** (раздел «Безопасность» → HTTPS) или `localhost` | Браузеры запускают сервис-воркер и предлагают установку только в защищённом контексте. По `http://IP` в **iOS** ярлык на экран «Домой» всё равно добавится (как закладка в полноэкранном режиме), в **Android** получится лишь ярлык сайта, без офлайн-оболочки |
| Манифест `manifest.webmanifest` и иконки 192/512 px | Требования Chrome к установимости; проверяется тестом `pwa.test.ts` и в браузере (Chrome DevTools → Application → Manifest) |
| Иконка `apple-touch-icon.png` (180 px) | iOS берёт её для экрана «Домой» |

Как установить:
- **Android (Chrome, Edge, Samsung Internet):** кнопка «Приложение» (иконка телефона) в шапке открывает системный диалог установки, либо меню браузера ⋮ → «Установить приложение».
- **iOS (Safari):** «Поделиться» → «На экран „Домой“» (кнопка в шапке показывает эти шаги: в iOS программно вызвать установку нельзя).
- **Компьютер (Chrome, Edge):** кнопка «Приложение» в шапке или значок установки в адресной строке.

В режиме приложения кнопка установки скрыта (`display-mode: standalone` и `navigator.standalone` для iOS).

## Сервис-воркер (`public/sw.js`)

Воркер работает только в защищённом контексте и регистрируется в `main.tsx` (`registerServiceWorker`, только в сборке, не в `npm run dev`).

| Что | Стратегия |
|---|---|
| Навигация (адреса интерфейса) | сеть (таймаут 6 с) → при обрыве сохранённая оболочка `/` → страница «Нет связи» (503) |
| `/assets/*` (файлы сборки с хэшем в имени) | сначала кеш; в кеш попадают только успешные не-HTML ответы; не более 120 файлов |
| Иконки, `manifest.webmanifest`, `favicon.svg` | из кеша с обновлением в фоне |
| **`/api`, `/sub`, `/ws`, `/.well-known`, запросы с `Authorization`, не-GET, чужие источники** | **воркер не трогает: запрос идёт в сеть, ничего не кешируется** |

**Данные панели в кеш не попадают никогда:** в ответах API токены, адреса нод и конфигурации с приватными ключами клиентов (инвариант 44). После
выхода из панели на устройстве не остаётся ничего, кроме собранного интерфейса. Новый кеш — только с тестом в `client/src/sw.test.ts`.

Обновление панели: `sw.js`, `index.html` и манифест отдаются с `Cache-Control: no-cache` (`static-cache.ts`), файлы `/assets` — `immutable` на год.
Оболочка берётся из сети, поэтому после обновления панели телефон получает новую версию при следующем открытии; воркер сам активируется
(`skipWaiting` + `clients.claim`), кеши прежних версий удаляются при активации. Если поменять стратегию кеширования несовместимо — поднимите
`SHELL_CACHE`/`ASSET_CACHE` в `sw.js` (`-v2`).

## Связь пропала

- Запуск без сети: оболочка открывается из кеша, проверка сессии не проходит, и вместо формы входа показывается `ConnectionLost` («Нет связи с
  панелью»; токен **не стирается**, повтор по кнопке, при возврате сети и раз в 10 секунд). Различие простое: 401 стирает токен (`api/index.ts`),
  значит «токен остался» = запрос не дошёл (`resolveSession` в `App.tsx`).
- Связь пропала в работе: остаются последние полученные данные и баннер «Нет связи с панелью»; при событии `online` данные обновляются сразу.

## Мобильная вёрстка

`viewport-fit=cover` и безопасные зоны (`pt-safe`, `pb-safe`, `bottom-safe-4` в `index.css`; в обычном браузере отступы нулевые), `100dvh`
вместо `100vh` (панели браузера на телефоне), в полях ввода на узких экранах 16 px (иначе iOS приближает страницу при фокусе), нет задержки
нажатия (`touch-action: manipulation`). Масштабирование жестами не отключено. Окна выводятся порталом в `body`: предок с `backdrop-filter` (шапка)
превращает `position: fixed` в «относительно предка».

## Иконки

Все иконки рисуются из одного описания скриптом `client/scripts/make-icons.cjs` (кольцо панели и три ноды-спутника; maskable-вариант вписан в
безопасную зону 80%). Перерисовать: `NODE_PATH=$(npm root -g) node client/scripts/make-icons.cjs` (нужен Playwright с Chromium), затем закоммитить PNG.
Цвет фона иконок, `theme_color` манифеста, `<meta name="theme-color">` и токен `--color-page` совпадают — это проверяет `pwa.test.ts`.

## Проверка вручную

Chrome → DevTools → Application: Manifest (нет ошибок, «Installability» зелёная), Service Workers (activated), Cache Storage (только `dementia-shell-v1` и
`dementia-assets-v1`, в них нет `/api`). Network → Offline → перезагрузка: «Нет связи с панелью». Lighthouse → PWA.
