# Перенос панели на другой сервер

Перенос выполняет тот же `install.sh`, что и обычная установка, но вместо пустой панели разворачивает копию прежней: логин и
пароль администратора, ноды (с SSH-доступами), клиентов, пользователей и подписки, партнёров, токен Cloudflare, настройки,
накопленный трафик. VPN-трафик пользователей панель не передаёт, поэтому во время переноса он не прерывается: ноды ничего не
замечают, пока не начнёт управлять ими новая панель.

Код — `server/src/utils/migration-archive.ts` (формат), `services/migration.service.ts` (прежняя панель),
`services/migration-import.service.ts` и `services/migration-client.ts` (новая панель), `routes/migration.ts`,
`middleware/migration-guard.ts`, CLI `server/src/cli/migration.ts`, интерфейс `MigrationCard.tsx`, режим в `install.sh`.

## Как проходит перенос

1. **Прежняя панель** — «Безопасность → Перенос панели на другой сервер → Подготовить перенос». Нужен пароль администратора
   (неверные пароли ограничены, как при смене пароля). Панель показывает **код переноса** (25 символов, ≈125 бит; один раз,
   действует час).
2. **Новый сервер** — тот же однострочник установки (`curl -sSL …/install.sh | sudo bash`), вопрос «2) Перенос панели».
   Установщик спрашивает адрес прежней панели (`https://panel.example.com:3001`; можно путь к скачанному файлу архива), код
   (ввод скрыт) и порт новой панели (по умолчанию тот же, что у прежней: в ссылках подписок есть порт).
3. Установщик ставит Node.js и собирает панель как обычно, затем забирает архив у прежней панели и **выбирает сертификат**
   (ниже).
4. Служба запускается; установщик сообщает прежней панели о завершении (`finish`): та **замораживается**, а её ссылки подписок
   перенаправляются (HTTP 308) на новый адрес.

Логин и пароль администратора переезжают без изменений (установщик показывает прежний логин, пароль не печатается). Если
нужны новые — `PANEL_USER` / `PANEL_PASSWORD` / `PANEL_RESET_CREDENTIALS=1`, как при обычной установке.

## Сертификат HTTPS на новом сервере

Сертификат привязан к имени, поэтому после переноса его нужно получить заново (или оставить прежний). Установщик спрашивает в
терминале; без терминала выбор задаёт `PANEL_CERT_MODE` (`cf`, `http`, `ip`, `custom`, `keep`, `none`).

| № | Способ | Что нужно | Как работает |
|---|---|---|---|
| 1 | Let's Encrypt через **Cloudflare API** (DNS-01) | Домен в Cloudflare (можно **новый**); токен с правом Zone:DNS:Edit | Если токен был сохранён в прежней панели, он приехал в архиве (расшифровывается перенесённым ключом) и **используется сам** — вводить не нужно. Иначе установщик спросит токен. Домен не обязан уже указывать на новый сервер: проверка идёт через TXT-запись. Установщик предлагает создать/обновить A-запись домена на IP нового сервера (как флажок в разделе «Безопасность») |
| 2 | Let's Encrypt по **HTTP-проверке** (HTTP-01) | Домен, **уже** указывающий на этот сервер; свободный порт 80 | Перед выпуском `dns-check` сравнивает A-запись домена с внешним IP сервера и предупреждает о расхождении (выпуск всё равно можно попробовать). Порт 80 открывается в ufw/firewalld; выпуск поднимает временный сервер на 80 |
| 3 | Самоподписанный сертификат на **IP** | Ничего | Браузер покажет предупреждение. **Подписки по `https://` работать не будут** — приложения не принимают такой сертификат; ссылки `http://` работают, но ключи в них идут без шифрования. Установщик и раздел «Безопасность» предупреждают об этом и просят подтвердить |
| 4 | **Свой сертификат**: путь к файлам | Файлы сертификата (fullchain) и ключа уже лежат на новом сервере | Установщик проверяет, что файлы читаются, ключ подходит к сертификату, срок не истёк; домен берётся из сертификата. Автопродления нет |
| 5 | **Оставить сертификат прежней панели** | Прежний сертификат действителен | Показывается, только если в архиве есть годный сертификат. Файлы и режим выпуска переезжают, поэтому автопродление (Cloudflare/HTTP-01) продолжает работать. Подходит, когда домен остаётся прежним и его запись A переключена на новый сервер |
| 6 | Без HTTPS | — | Панель стартует по HTTP; включить HTTPS можно позже в разделе «Безопасность» |

Вариант 5 добавлен сверх четырёх запрошенных: при переносе на тот же домен он единственный не требует ни токена, ни открытого
порта, ни ожидания DNS. Без терминала по умолчанию выбирается 5 (если сертификат годен), иначе 6. Если выпуск не удался и
терминала нет, установщик не обрывает перенос на полпути: панель запускается без HTTPS и сообщает об этом.

### Домен, порт и ссылки подписок

Ссылка подписки — `<публичный адрес>/sub/<токен>`; приложения пользователей хранят её целиком, включая домен и порт.

- **Домен и порт прежние** (рекомендуется): переключите запись A домена на IP нового сервера — все ссылки продолжат работать без
  действий пользователей. Сертификат для этого — вариант 1 (его можно выпустить **до** переключения DNS) или 5.
- **Домен или порт новые**: ссылки прежней панели работают, пока включён старый сервер: он перенаправляет `/sub/…` на новый
  адрес (308 с тем же путём). Не выключайте его, пока пользователи не получат новые ссылки. Явно заданный «Публичный адрес
  панели» в настройках автоматически заменяется на адрес новой панели.
- Партнёры, подключённые к вашим нодам, и панели, к которым подключены вы, хранят прежний адрес: при смене адреса его нужно
  обновить на их стороне (партнёрский API замороженной панели отвечает 410).

## Состояния прежней панели

| Состояние | Когда | Что происходит |
|---|---|---|
| `idle` | обычная работа | — |
| `prepared` | выдан код, архив не забирали (час) | панель работает как обычно |
| `exporting` | архив передан (сетью или скачан файлом) | **любые записи через API отклоняются (423)**, фоновый опрос нод, партнёров и продление сертификата на паузе, сверху интерфейса — баннер. Блокировка снимается завершением, отменой («Отменить перенос») или сама через 2 часа |
| `migrated` | новая панель запущена | панель заморожена: вход и API отвечают 410 с адресом новой, `/sub/*` перенаправляется. Вернуть работу: `cd /opt/demension-panel && node server/dist/cli/migration.js resume`, затем `systemctl restart demension` |

Блокировка записей нужна, потому что снимок БД уже снят: клиент или нода, добавленные после него, на новой панели не появились бы,
а её синхронизация удалила бы лишнее с нод (инвариант 10).

## Что в архиве и как он защищён

Файл `*.dpm`: `DMPANEL1 | iv | tag | AES-256-GCM(gzip(JSON))`. Внутри — манифест (версия панели, версия схемы БД, число нод и
клиентов, сведения о сертификате — для вопросов установщика) и только файлы из белого списка (`ARCHIVE_FILES`): `demension.db`
(консистентный снимок `VACUUM INTO` без сессий и служебных данных переноса), `secret.key`, `ssl/fullchain.pem`,
`ssl/privkey.pem`, `ssl/acme-account.key`. Любое другое имя в архиве — ошибка (запись за пределы каталога данных невозможна).

- Из кода переноса HKDF-SHA256 выводит два независимых значения: ключ шифрования архива (`enc`) и доказательство знания кода
  (`auth`, заголовок `X-Migration-Auth`). **Сам код по сети не передаётся и не хранится**: панель держит в `settings` только ключ
  `enc` (зашифрованный мастер-ключом) и SHA-256 от `auth`.
- Поэтому архив безопасен и по обычному HTTP, и при самоподписанном сертификате прежней панели: подделать или прочитать его без
  кода нельзя. Клиент сначала проверяет TLS строго, и только при ошибке сертификата повторяет запрос без проверки.
- Неверные коды ограничены: 10 за 15 минут с одного IP (429).
- Архив содержит ключ шифрования и приватный ключ TLS — храните скачанный файл как секрет и удалите после переноса.

## Импорт (новый сервер)

`importMigrationArchive` до запуска службы: расшифровывает архив → проверяет, что `DEMENSION_SECRET_KEY` в окружении (если задан)
совпадает с ключом из архива → при наличии панели с данными требует `--replace` (CLI завершается кодом 3, установщик
спрашивает подтверждение; копия сохраняется в `data/backups/pre-migration-…`) → кладёт файлы на место → открывает БД, отказывает
архивам от более новой схемы, применяет недостающие миграции (архив от старой версии обновляется), удаляет сессии и служебные
настройки переноса → проверяет, что секреты расшифровываются ключом из архива. **При любой ошибке прежние файлы
восстанавливаются.**

В `server/.env` переменная `DEMENSION_SECRET_KEY` на новом сервере удаляется (ключ приезжает в `data/secret.key`); остальные
добавленные вручную переменные (`TRUST_PROXY`, `DEMENSION_UPDATE_CHECK`…) на новый сервер **не переносятся** — добавьте их.

## CLI `server/dist/cli/migration.js`

| Команда | Где | Что делает |
|---|---|---|
| `pull --from URL [--replace]` | новый | забирает архив у прежней панели и импортирует (код — `MIGRATION_CODE`) |
| `file --path F [--replace]` | новый | то же из скачанного файла |
| `dns-check --domain D` | новый | сравнивает A-запись домена с внешним IP сервера |
| `ssl --mode keep\|cf\|http\|ip\|custom\|none …` | новый | выбор сертификата (`--domain --email --ip --cert --key --a-record yes\|no`, токен — `CF_API_TOKEN`) |
| `url --host H --port P [--scheme]` | новый | обновляет явно заданный публичный адрес, печатает адрес новой панели |
| `finish --from URL [--new-url U]` | новый | замораживает прежнюю панель, включает перенаправление подписок |
| `resume` | прежний | снимает блокировку/заморозку |

Результат для скриптов — строки `@@ключ=значение`; ошибки — в stderr, код 1 (аргументы — 2, нужен `--replace` — 3).

## Переменные установщика

`MIGRATE=1`, `MIGRATE_FROM`, `MIGRATE_FILE`, `MIGRATION_CODE`, `MIGRATE_REPLACE=1`, `PANEL_PORT`, `PANEL_CERT_MODE`,
`PANEL_DOMAIN`, `PANEL_EMAIL`, `CF_API_TOKEN`, `PANEL_CERT_FILE`, `PANEL_KEY_FILE` — полностью автоматический перенос:

```bash
curl -sSL https://raw.githubusercontent.com/ghostoftheeleven/demension-panel/main/install.sh | \
  sudo MIGRATE_FROM=https://panel.example.com:3001 MIGRATION_CODE=XXXXX-XXXXX-XXXXX-XXXXX-XXXXX PANEL_CERT_MODE=keep bash
```

## После переноса

- Проверьте ноды: статусы появятся после первого опроса (до минуты). SSH-ключи хостов (TOFU) переехали, повторного
  доверия не требуется.
- Если нода ограничивает SSH по IP панели (фаервол провайдера, `ignoreip` в fail2ban, настроенный при установке), добавьте IP
  нового сервера — панель этого не меняет.
- Отключите прежний сервер, убедившись, что ссылки подписок обновлены (см. выше).

## Ограничения

- Перенос идёт между панелями одной линии версий: архив от более новой панели не принимается, более старой — обновляется.
- Две работающие панели не должны управлять одними нодами: поэтому прежняя панель замораживается. Отмена переноса после запуска
  новой панели возвращает именно эту ситуацию — сначала остановите новую.
