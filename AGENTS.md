# AGENTS.md — руководство для ИИ-агентов и разработчиков

Dementia Panel — агентлесс-панель управления нодами **AmneziaWG**: разворачивает AmneziaWG в Docker на удалённых
серверах по SSH, выдаёт клиентские конфиги и автообновляемые подписки, умеет подключать уже установленные серверы
(в т.ч. из приложения AmneziaVPN) и делиться нодами между панелями. До v0.1.4 проект назывался **Demension** — см. инвариант 36.

Перед любыми изменениями прочитайте этот файл целиком, а затем документ подсистемы, которую трогаете.

## Структура репозитория

```
server/            Node.js 22.13+ / Express 4 / TypeScript, SQLite через node:sqlite
  src/index.ts       точка входа: HTTP+HTTPS на одном порту, WebSocket, фоновые задачи
  src/db/index.ts    схема и миграции (PRAGMA user_version)
  src/routes/        HTTP API
  src/services/      бизнес-логика (SSH, провижининг, подписки, партнёры, HTTPS…)
  src/utils/         чистые функции (сети, параметры AWG, ключи Amnezia, HTTP-утилиты)
  src/scripts/deploy-awg.sh  скрипт развёртывания ноды (передаётся по SSH через stdin)
  src/scripts/deploy-bridge.sh  установка моста (iptables DNAT, без Docker; тоже через stdin)
  src/scripts/update-panel.sh  обновление панели из интерфейса (systemd-run → install.sh релиза, откат при сбое)
  src/cli/reset-admin.ts     сброс логина/пароля администратора
  src/cli/migration.ts       перенос панели на другой сервер (его вызывает install.sh)
  src/middleware/    авторизация, ограничение частоты, заголовки безопасности (CSP), единый обработчик ошибок
  test/              vitest: *.test.ts, helpers/ (API, БД, подмена SSH и панели партнёра, процесс панели), docker/ (тестовые ноды)
client/            React 19 + Vite + Tailwind 4 (SPA, собирается в client/dist и раздаётся сервером)
  src/index.css      тема Bento: семантические цвета (page, card, line, ink, muted, mint, on-accent…), шрифты
install.sh         установка панели на VPS (systemd)
docs/              документация
```

## Команды

```bash
npm install --prefix server && npm install --prefix client
npm run dev:server            # бэкенд :3001 (tsx watch)
npm run dev:client            # фронтенд :3000, прокси /api, /sub, /ws на :3001
cd server && npx tsc --noEmit && npm test     # проверка типов и тесты сервера (≈ 1–2 мин)
cd client && npx tsc -b && npm run lint && npx vite build
npx shellcheck -S error install.sh server/src/scripts/deploy-awg.sh server/src/scripts/deploy-bridge.sh server/src/scripts/update-panel.sh server/test/docker/nodes.sh server/test/docker/entrypoint.sh
server/test/docker/nodes.sh up                # реальные ноды в Docker для real-*.test.ts (без них эти тесты пропускаются)
server/test/install/run.sh                    # install.sh целиком в чистом Ubuntu + перенос панели между двумя контейнерами + обновление с предыдущего релиза (Docker, ≈ 20 мин) — гонять при любой правке install.sh
```

CI (`.github/workflows/ci.yml`) выполняет всё перечисленное на каждый push в `main`; отдельное задание `e2e` поднимает тестовые
ноды и гоняет весь набор вместе с Docker-тестами.

## Правила работы с репозиторием

- Готовая работа коммитится и пушится **сразу в `main`** (так решил владелец проекта). Без force-push.
- Shell-скрипты хранятся с LF (`.gitattributes`). На Windows с `core.autocrlf=true` рабочие файлы могут быть с CRLF —
  учитывайте это в скриптах, которые патчат исходники.
- Тексты интерфейса и сообщения об ошибках — на русском.
- Оформление интерфейса — Bento (выбрал владелец): тёмный фон, плитки `bg-card border border-line rounded-2xl`, сочные плоские
  акценты (лайм `bg-mint`, оранжевый, голубой, розовый), кнопки-действия — пилюли `rounded-full btn-press`, заголовки Unbounded.
  Цвета — только семантические токены из `client/src/index.css` (`bg-card`, `text-muted`, `bg-ok-soft text-ok`…), не палитра
  Tailwind (`zinc`, `emerald`…), без градиентов. **Текст на яркой заливке — `text-on-accent`**, а не `text-ink` (он светлый).
- Новые функции и правки поведения сопровождайте тестами в `server/test` и обновлением документа в `docs/`; новое правило,
  которое легко нарушить, — пунктом в инвариантах ниже. Изменили данные для ИИ-агентов (этот файл, `docs/`) — обновляйте их в том
  же коммите. Правила тестов — [docs/testing.md](docs/testing.md): проверяйте реальный код, тест на баг должен падать на старом коде,
  SSH и чужие панели подменяйте хелперами (`stubSsh`, `stubRemotePanel`).

## Версии и релизы

История изменений ведётся релизами GitHub в формате **`vX.Y.Z`** (правила задал владелец, это **не** обычный semver):

- **X** — только сверхкрупные, масштабные переработки (новая мажорная версия).
- **Y** — исправление **критических** уязвимостей и багов, которые приводили к утечкам данных или критическим сбоям панели.
- **Z** — небольшие изменения: обычные баги, потенциальные уязвимости, доработки и новые функции, не приводившие к серьёзным сбоям.

Младшие цифры при повышении обнуляются; номер выбирается по самому серьёзному изменению в релизе. Версия — только поле
`version` корневого `package.json`; к каждому изменению поведения добавляйте запись в `CHANGELOG.md` (первый раздел
`## vX.Y.Z — дата` = текущая версия) и повышайте версию. Тег и релиз создаёт `.github/workflows/release.yml` после зелёного
CI на `main`. Подробно — [docs/releases.md](docs/releases.md).

## Критические инварианты — не ломать

Каждый пункт — реальная ошибка, которая уже была или легко возникает. Если изменение затрагивает пункт, перечитайте
соответствующий документ.

### Безопасность
1. **API никогда не отдаёт секреты.** `serializeServer` (routes/servers.ts) вырезает `ssh_password`, `ssh_key`,
   `server_private_key`, `preshared_key`; `serializeClient` — `client_private_key`. Приватный ключ клиента попадает
   только в `.conf`/QR/подписку.
2. **SSH-пароли/ключи и токен Cloudflare хранятся зашифрованными** (`encryptSecret`/`decryptSecret`, ключ
   `data/secret.key` или `DEMENTIA_SECRET_KEY`). Никогда не пишите их в БД напрямую и не логируйте.
3. **Токены сессий и партнёров хранятся только как SHA-256.** Сам токен показывается один раз.
4. **Токен авторизации — только в заголовке `Authorization: Bearer`.** Не принимайте его из query-string; скачивание
   конфигов идёт через `fetch` + Blob. WebSocket авторизуется первым сообщением `{type:'auth', token}`.
5. **Никакой подстановки пользовательских данных в shell.** Значения для удалённых команд проходят валидацию и
   `shellQuote`; локальные команды — через `execFile` с массивом аргументов (см. fail2ban.service.ts).
6. **Async-обработчики Express 4 оборачивайте в `asyncHandler`.** Иначе отклонённый промис завершит процесс. Ошибки
   для пользователя бросайте как `HttpError(status, message)`.
7. **Каждый WebSocket должен иметь `ws.on('error')`** — иначе один битый фрейм роняет панель.
8. Партнёрский API работает **только по HTTPS** (`req.secure`); исключение — `ALLOW_INSECURE_FEDERATION=1` для разработки.

### Ноды и VPN
9. **Все операции с одной нодой идут через очередь `runExclusive`** (provision.service.ts). Синхронизацию запрашивайте
   через `ProvisionService.requestSync(serverId)` — не вызывайте SSH-команды напрямую из роутов.
10. **Конфиг ноды генерируется целиком из БД** (`AwgService.generateServerConfig`). Всё, чего нет в БД, при
    синхронизации исчезнет с ноды. Поэтому пиры при импорте сохраняются как клиенты (`external = 1`).
11. **Операции с контейнером — через поля сервера** `container_name`, `iface`, `conf_path`, `awg_tool`, `managed_by`
    (контейнер может быть чужим — приложения Amnezia, с `wg0`/`wg`). Не хардкодьте `amnezia-awg`/`awg0`.
12. **`awg syncconf` не меняет параметры интерфейса.** Смена обфускации требует `requestApply` (перезапуск контейнера),
    смена порта — переустановки (`deployed_port !== awg_port`). Подсеть при наличии клиентов менять нельзя.
13. **Клиент активен на ноде** только если `enabled = 1`, `owner_blocked = 0`, его подписчик активен
    (`enabled` и не `suspended`), а для клиента партнёра — доступ включён, не приостановлен и нода не отозвана.
    Логика в одном месте — SQL в `ProvisionService.getServerClients`. Используйте его.
14. **Трафик накапливается дельтами** (`rx_counter`/`tx_counter`), потому что счётчики интерфейса сбрасываются.
    `total_rx` — отправлено клиентом (upload), `total_tx` — получено клиентом (download).
15. **На ноды всегда ставится `amneziavpn/amneziawg-go:latest`** (решение владельца). Образ только amd64.
16. Ноды партнёра (`servers.remote_panel_id IS NOT NULL`) не имеют SSH: любые SSH-операции для них запрещены
    (`loadLocalServer` / `getLocalServerOr404`), синхронизация уходит в `FederationClient`.

### Протокол и подписки
17. **Параметры AWG проверяются `validateAwgParams`** (utils/awg-params.ts) при любом изменении пользователем:
    `S1+56 ≠ S2`, `Jmin ≤ Jmax ≤ 1280`, H1–H4 не пересекаются, с `HeaderProtectionKey` все S1–S4 ≥ 12, `S4 ≤ 32`.
    Импортированные с ноды параметры сохраняются как есть, даже если не проходят проверку.
18. **Новые серверы получают параметры актуальной версии (3.x); существующие версии 1.x не меняются молча** — только
    по действию «Перейти на 3.x» (иначе у всех клиентов пропадёт VPN).
19. **HTTP-заголовки — только ASCII.** Тексты (название, описание, объявление) передаются как `base64:…`, имена
    файлов — через `contentDisposition()`. Кириллица в `setHeader` роняет запрос с `ERR_INVALID_CHAR`.
20. **Ссылки подписки, выданные по `http://`, должны продолжать работать после включения HTTPS.** Поэтому HTTP и HTTPS
    обслуживаются на одном порту, а `/sub` и ACME-challenge доступны по HTTP.

### База данных
21. **Схема меняется только новой миграцией** в конец массива `migrations` (db/index.ts). Существующие миграции не
    редактируйте — они уже применены у пользователей. Колонки добавляйте через `addColumn`.
22. Связанные изменения (создание клиента + выделение IP и т.п.) — в `transaction()`. Уникальность IP клиента на
    сервере обеспечивает индекс `idx_clients_server_ip`, уникальность публичного ключа — `idx_clients_server_pubkey`
    (перед сменой ключа клиента проверяйте, что он не занят другим клиентом ноды).

### Клиенты и конфиги
23. **Имя клиента на ноде партнёра — не длиннее 64 символов**, иначе владелец отвечает 400, и клиент навсегда остаётся
    `pending:`. Имя пира пользователя строится `subscriberPeerName`, имя для панели владельца — `normalizePeerName`
    (utils/names.ts).
24. **`PresharedKey` / `pre-shared-key` пишется в конфиг, только если ключ есть** (иначе в файл попадёт `null`).
    `AllowedIPs = 0.0.0.0/0, ::/0` — намеренно, защита от утечки IPv6 мимо туннеля (docs/subscriptions.md).
25. **Всё, что пришло от чужой панели, проверяйте по формату до записи в БД** (`sanitizeRemoteNode/Peer/Params`): эти значения попадают
    в .conf пользователей, а перевод строки в них даёт инъекцию директив (`PostUp` выполняется на устройстве клиента).
26. **Установка панели на ноду не должна удалять чужой контейнер AmneziaWG**: у приложения Amnezia тот же `amnezia-awg`, а его
    конфигурация и клиенты лежат внутри контейнера. Перед установкой работает `ProvisionService.findForeignContainer`;
    контейнер панели опознаётся по `demension.env` на хосте **и** проброшенному каталогу `/opt/amnezia/awg`. Не удаляйте этот
    контроль и не вызывайте `deploy-awg.sh` в обход `doInstall`.
27. **Логин и пароль администратора случайные** (`AuthService.randomLogin/randomPassword`), «admin/admin» и пароли по умолчанию
    недопустимы. `install.sh` выводит адрес панели, логин и пароль один раз; пароль не пишется в `.env`, БД (только хэш), журнал.
28. **Панель уже работает у пользователей — обновление не должно ломать установку.** Порт/подсеть/параметры, которые не удалось
    применить на ноде, откатываются в БД (`applyOrRollback`, routes/servers.ts): подписки не должны раздавать то, чего нет на ноде.
    `install.sh` скачивает обновление до остановки службы и сохраняет добавленные вручную переменные `server/.env`
    (в т.ч. `DEMENTIA_SECRET_KEY` — без него не расшифровать SSH-доступы).

### Перенос панели, проверка из стран, учётная запись
29. **Архив переноса** (`utils/migration-archive.ts`) восстанавливает только файлы из белого списка `ARCHIVE_FILES`; **код переноса не хранится и не
    передаётся по сети** — в `settings` лежат производные (ключ `enc` под мастер-ключом и SHA-256 от `auth`). Всё, что добавляется в БД или в `data/`,
    должно попадать в снимок (`VACUUM INTO`) и импорт (`importMigrationArchive`). Модули, которые выполняются **до** открытия БД
    (`migration-archive.ts`, `migration-import.service.ts`, `migration-client.ts`, CLI), не импортируют `db/index.ts` статически.
30. **Пока панель в состоянии `exporting`/`migrated`**, `migrationGuard` отклоняет записи (423/410; установку нод по WebSocket — проверка в `index.ts`), а `MigrationService.isBackgroundPaused()` останавливает
    фоновые задачи (опрос нод, партнёры, продление сертификата, проверки из стран): две панели не должны управлять одними нодами. Новый фоновый
    цикл обязан проверять `isBackgroundPaused()`.
31. **Подтверждение паролем** при смене логина/пароля и выдаче кода переноса считается в `reauthLimiter` (5 неверных за 15 минут на администратора).
32. **Проверка из стран выключена по умолчанию**: пока администратор не включил её, адреса нод никуда не отправляются. Ответы check-host.net — внешние
    данные, проверяются по формату (`ProbeService`); пометки в названии/описании подписки идут только через `getNameMarks`/`getLegend`
    (описание — `base64:`, инвариант 19).
33. **`/api/health` отвечает по HTTP и при включённом HTTPS**: `install.sh` проверяет запуск панели через `http://127.0.0.1:порт/api/health`.
34. **Обновление из интерфейса запускает `install.sh` *нового* релиза скриптом *установленной* версии** (`update-panel.sh`, docs/releases.md).
    Поэтому `install.sh` обязан поддерживать `PANEL_UPDATE_REF=vX.Y.Z` (ff-merge тега вместо `git pull`) и работу без терминала без
    вопросов и без смены учётных данных; аргументы `update-panel.sh` (каталог, каталог состояния, версия, текущая версия) и формат
    `data/update/status.json` не меняйте несовместимо. Процесс обновления живёт в отдельной службе `systemd-run`, а не в дочернем процессе панели.
35. **Интерфейс не загружает ничего извне** (CSP: `default-src 'self'`, security-headers.ts): шрифты и прочие файлы лежат в сборке
    (`@fontsource/*`, `client/src/assets`), а `assetsInlineLimit: 0` в vite.config.ts не даёт встроить их как `data:` — такие шрифты CSP
    блокирует. CI проверяет CSS сборки.
36. **Проект переименован Demension → Dementia (v0.1.4), уже установленные панели должны продолжить работать.** `install.sh`
    переносит `/opt/demension-panel` в `/opt/dementia-panel` (старый путь — ссылка), служба `dementia.service` с псевдонимом
    `demension.service`, `DEMENSION_*` в `.env` → `DEMENTIA_*`. Код читает переменные через `panelEnv()` (utils/env.ts, оба имени),
    `config.ts` подхватывает `data/demension.db` (`adoptLegacyDatabase`), клиент — прежний ключ токена. **Не переименовывать:**
    имя БД и соль KDF в архиве переноса (`ARCHIVE_DB_ENTRY`, migration-archive.ts — архивы старых панелей), `managed_by = 'demension'`
    (значение в БД, задано старой миграцией), метку `/opt/amnezia/awg/demension.env` на нодах (её читает start.sh работающих контейнеров).

### Проверка доступности и мосты
37. **Доступность ноды засчитывается по журналу заглушки на самой ноде, а не по ответу.** Ответ ICMP/TCP подделывается по дороге, поэтому
    ping не используется, а у заглушки `dementia-probe` результат подтверждается `matchStubHits` (одноразовая метка HTTP, адрес отправителя
    UDP). Заглушка — отдельный контейнер в `/opt/dementia-probe`: она не должна трогать контейнер AmneziaWG и `/opt/amnezia`, ставится только
    при включённой проверке (инвариант 32), удаляется вместе с нодой (`teardown`). Строки журнала разбираются только строгого формата (`parseStubHits`).
38. **Правила моста генерируются целиком из БД** (`buildBridgeRules`, как конфиг ноды) и применяются через очередь `runExclusive` по ключу
    `bridge:<id>`; изменения нод доходят до мостов через сравнение `rules_hash` в `BridgeService.checkAll`. Адрес ноды — только после
    `isValidHost` и в `shellQuote`; IPv6-ноды мост не пересылает. **`listen_port` привязанной ноды не меняется** — по нему подключаются
    пользователи, получившие мост в подписке.
39. **Мост выдаётся в подписке только через `BridgeService.routesFor`**: мост `online`, `check_ok` не `0`, режим `always` или `auto` с
    `bridge_state.active`. Меняется только адрес `Endpoint` (ключи и параметры обфускации — ноды). Решение «нужен мост» — только в
    `BridgeService.evaluate` с гистерезисом (2 проблемные проверки для включения, 3 удачные и 12 часов для выключения): адрес у
    пользователей не должен меняться при каждом обновлении подписки.

40. **2FA и резервные копии не раскрывают секреты.** TOTP-секрет шифруется, recovery codes хранятся только как SHA-256 и показываются один раз; отключение/перевыпуск требуют пароль. Резервный архив шифруется отдельным ключом, сессии в него не попадают; фоновые копии и Telegram останавливаются `MigrationService.isBackgroundPaused()`, ошибки провайдеров не блокируют панель.
